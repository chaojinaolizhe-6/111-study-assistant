# 使用说明（大学物理学习助手工作区）

> 本工作区 = 开源模板 tutor（辅导协议 + SM-2 间隔复习 + 文件状态）+ 自写的周排期脚本 + 自建的能力证据账本。
> 架构与设计依据见 `ARCHITECTURE-架构.md`；来源与版本见 `upstream/PROVENANCE.md`；功能核实见 `AUDIT-审查报告.md`。
> 中心原则：**收集"没有帮助时能做什么"的证据，并据此安排下一次学习**；辅导后做对 ≠ 独立掌握。

## 1. 资料放哪里

| 资料 | 位置 |
|------|------|
| 某门课课件（PDF/图片） | `subjects/NN-课程名/课件/`，例：`subjects/02-光学/课件/` |
| 某门课作业照片（多张可以） | `subjects/NN-课程名/作业/`，例：`subjects/01-理论力学/作业/` |

放好后在对话里说一声（例："光学课件放进去了"），我会读入、登记到对应 INDEX，并把作业按截止日期纳入周计划。
放文件本身不改变学习状态（上传 ≠ 学会）；课件三态（老师已讲/我已看过/能独立完成）在辅导中核实后登记。

## 2. 如何开始一次学习（三种模式 + 提示梯度）

- `/learn` —— 学习模式（**默认，含作业**）：短暂独立尝试 → 定位瓶颈 → 讲解或最小充分提示 → 你继续推导 → 撤去支持 → 一道**无提示新题**检查
- `/test <主题或题目>` —— 测验模式：只澄清题意，不给方法提示；作答提交后才反馈
  （**仅在**你明确要求测验、或双方约定做短诊断时使用——不默认套用到所有作业）
- "给我完整讲一下 XX" —— 示例学习模式（明确要求时切换，会记录已见解答，之后必做新题检验）
- `/review` —— 只做今天到期的记忆复习；`/status` —— 看记忆与能力两套状态

> 说"我不会 / 缺基础 / 给我讲个例子"时，直接进入教学，不硬卡着不给方法。

提示梯度（按瓶颈升级，不按聊天轮数；独立跨过一个瓶颈后从低支持重新开始）：
H0 澄清目标/条件 → H1 提醒相关概念 → H2 指出局部结构 → H3 给待补全的式子 → H4 示范一步/讲类似例题。

每次作答我都会记录：初次独立表现、提示级别、辅导后表现、是否见过解答、实际用时——
**提示后做对记为学习进展，不计为独立通过。**

## 3. 状态保存在哪（换对话能继续）

- 记忆状态：`state/`（SM-2：到期复习队列、复习日志、弱项）——管"何时再测"
- 能力状态：`learning/`（goals.yaml、tasks/、attempts.jsonl、learner-state.json、policy.yml）——管"无帮助下通过了什么"
- 续学入口：根目录 `AGENTS.md` 的 STATUS 块（自动注入每次对话）+ `state/due.md`
- 能力等级：未测 → 需支持 → 曾独立完成 → 延迟通过 → 迁移通过；判定参数在 `learning/policy.yml`
  （独立通过=闭卷+无提示+未见解答；"有稳定证据"=≥2 个不同日期独立通过且含 ≥1 次首次作答即通过的未见变式，≠ 永久掌握）
- 计划是派生视图：`plan/week-plan.md` 与 `learning/learner-state.json` 都由脚本生成，勿手工编辑

## 4. 学期排期（三条队列 + 容量约束）

- 编辑 `plan/inputs.yml`：课程、作业（截止+预估耗时+设备）、时段、周专注预算、阶段比例
- 生成：`python -B tools/plan-week.py --inputs plan/inputs.yml --root . --out plan/week-plan.md`
- 三条队列竞争同一预算：记忆维护（到期概念）/ 能力建设（learning/tasks 未完成题目）/ 修复与再测（待修复错因）
- 规则：截止日期优先；白天平板/晚上电脑；每天最多用 70% 可用时间；周承诺 ≤ (1-缓冲)×周预算，超了显式告警
- 卡题时用检查点：35~45 分钟后判断"新推理/原地打转/缺前置/疲劳"，保存四要素（已完成什么/失败原因/当前障碍/下次先做什么）
- 注意：`inputs.yml` 时段是**待确认默认值**；真实作息、课表、截止日期拿到后告诉我

## 5. 已实测验证（边界场景见 mock/，全部为模拟数据；真实学习成效尚无证据）

- ✅ 模板复用：`.tutor/` 上游文件未改一行，扩展以新技能/新目录形式叠加
- ✅ 8 个 tutor 脚本 + 3 个新脚本（validate_attempts/derive_state/plan-week）在 Windows+Python 3.12 全部可运行
- ✅ 资料组织、状态保存与续学、SM-2 成功/遗忘路径、概念路径、严格校验
- ✅ 能力账本边界（mock，2026-09-24 两轮复核）：H2 辅导后做对不计独立通过；见过解答的旧变式重做通过不计迁移；
  开卷通过单独统计不计等级；升版换目标/换类别时旧事件按历史元数据（learning/tasks/history/）解释、不借用当前版本；
  无历史元数据的事件保留但不升级；题目曝光按整份日志全局计算（跨目标不能绕过）
- ✅ 排期边界（mock）：逾期 2 天概念未被过滤并排入当天补救；今日到期任务可排入当天；

- ✅ 事件校验负向测试：无关能力目标计分被拒绝（exit 1）；重复 event_id、测验模式带提示等同样被拒
- ⚠ **真实学习成效：未验证。** 真实实例目前只有 1 道基线题、0 条作答记录，无任何成效证据；
  上面全部结论只证明"功能按设计工作"，不证明学习效果。跨目标、跨版本的能力等级在真实数据积累后仍需校准

## 6. 尚未验证 / 已知限制（诚实声明）

- ✅ 作业照片读取（2026-09-26 更新）：模型已切换为支持视觉（deepseek-v4-flash-vision-exp），
  已实测可读答题卡截图（电工 C2H1 第 1 张）。**能读 ≠ 已读完**：读取范围按四级（登记/渲染/已读/已核验）分别记录。
- ⚠ 上游 `validate-study.py` 在导入 `obsidian/` 知识库后**必然报 FAILED**：知识库笔记里的数学记号（写成 `M[u]` 紧跟 `(P)` 这种形式）被链接正则误判（2026-09-26 实测 121 条）。
  **不要用"过滤输出"冒充通过**——改用范围化校验 `python -B tools/validate_study_scoped.py --today <日期>`：
  它按 `.tutor/config/validation-scope.yml` 分成 **范围内错误 / 范围外跳过 / 信息项**，只有范围内错误影响退出码，并明确打印跳过条数（2026-09-27 实测：范围内 0、范围外 122、信息项 1）。
- ⚠ 知识库质量：`verified` 标签是解构工具自评，单篇抽样**不代表整库正确**；给学习者的公式以课件/教材原书为准。
- ⚠ 排期脚本**不支持当日临时时间窗**（如"今天学到 13:00"）：临时窗口写在 `plan/today-YYYY-MM-DD.md`，当天以该文件为准，不跨天沿用。
- ⚠ 学习成效仍未验证：目前**2 条作答记录、0 个独立通过**，批改/提示/复习/续学闭环尚未经过真实学习过程检验。
- ⚠ 学习效果提升：tutor 声明无对照实验证据；本系统同样不声称已验证能改善学习效果，
  是否有效以你自己的延迟独立表现数据为准（PNAS 2025 研究提示：无约束 AI 可能损害撤去 AI 后的表现）。
- ⚠ 泄题防护是提示级约定 + 事件程序校验，不是绝对保证；参考解答与学生可见内容分离靠我的遵守，未经对抗性实测。
- ⚠ 真实课表/截止日期/作息/考试日期：全部未知，未编造；待你提供。
- ⚠ FSRS 未启用：当前唯一记忆调度器是 tutor 的 SM-2（已在流水线中校验）。
  积累评级数据后再评估 py-fsrs 迁移；不同时运行两个调度器。
- ⚠ 备选项目（anything-to-course、OpenTutor）未安装：首选项目适合复用，不堆叠多套系统。
- ⚠ 脚本控制台中文偶尔乱码（GBK）：只影响屏幕显示；运行前加 `$env:PYTHONIOENCODING='utf-8'`。

## 7. 常用命令（PowerShell）

```powershell
python -B .tutor/core/scripts/refresh-status.py --today 2026-09-27   # 刷新复习队列与日期标记
python -B tools/session-close.py --today 2026-09-27                  # 会话收尾：逐步校验/重建/同步，失败显式报出
python -B tools/validate_study_scoped.py --today 2026-09-27          # 范围化校验（范围内错误/范围外跳过/信息项）
python -B tools/validate_attempts.py                                 # 校验作答事件
python -B tools/validate_hurdles.py                                  # 校验困难观察（没有作答的"不会/不理解"）
python -B tools/derive_state.py                                      # 重建能力状态（派生）
python -B tools/append_attempt.py --file <事件.json>                  # 先校验后追加；重复 event_id 拒绝、失败回滚
python -B tools/sync_status.py --today 2026-09-27                    # 只同步 STATUS（叙述行取自 status-narrative.yml）
python -B tools/plan-week.py                                         # 生成三队列周计划
python -B mock/acceptance-20260927/run_acceptance.py                 # 隔离验收测试（不碰真实记录）
```

## 8. 建议的第一步（试点，按 v2 路线第 1~2 天）

1. 选一个主题（建议：一阶线性 ODE 或 静电学边界条件，你定）；
2. 我给你一道闭卷基线题，无提示作答（作答前自报一次信心）；
3. 按协议获得最小提示，记录真实卡点（事件落盘 + 程序校验）；
4. 几天后一道未见变式检查——这一次闭环的数据比继续设计系统更能决定下一步。
