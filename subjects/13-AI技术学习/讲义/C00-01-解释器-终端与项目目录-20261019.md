## 0. 这一单元为什么排在最前面

后面所有项目都会撞上同一类事故：代码一个字没改，昨天能跑、今天不能跑；或者「我明明装了包，它说找不到」。这类问题九成不是算法错，而是三个问题没分清——**哪个解释器在跑、我现在在哪个目录、这个路径从哪算起**。

本单元不写业务代码，只练一件事：把「源码 / 解释器 / 工作目录 / 输出」这四个对象分开，并且能在终端里当场验证。

## 1. 四个对象各是什么

| 对象 | 是什么 | 在本机长什么样 | 谁决定它 |
|---|---|---|---|
| 源码 | 你写的 `.py` 文本 | `show_paths.py` | 你 |
| 解释器 | 读源码、翻译并执行它的那个程序 | `python.exe` | 安装位置 ＋ 终端里敲的是哪个 `python` |
| 终端（PowerShell） | 把命令交给程序、并把输出显示出来 | 这个对话窗口背后的 shell | 你打开的窗口 |
| 工作目录 cwd | 当前「站在哪个文件夹里」 | 一个文件夹路径 | 终端，`cd` 改它 |
| 输出 | 程序打印的正文与报错 | 屏幕上的黑字与红字 | 程序 |

两条最容易被忽略的事实：

1. **源码自己不会运行。** 双击一个 `.py` 之所以能动，是因为系统替它找到了一个解释器。
2. **解释器不是只有一个。** 同一台机器上可以装好几个 Python，各自有各自的第三方包。

## 2. 同一条 `python`，可能落到两个不同的程序

这是本单元最值得先建立的一根神经。本机实测（2026-10-19）：

```
C:\Users\M\AppData\Local\Programs\Python\Python312\python.exe
C:\Users\M\AppData\Local\Microsoft\WindowsApps\python.exe
```

第一条是真解释器，Python 3.12.9。第二条 **0 字节**，是微软商店的「应用执行别名」占位文件——它根本不是一个 Python，多数情况下只会弹一个提示。

终端的查找规则是：**按 PATH 从左到右，第一个命中的被执行**。本机 PATH 的顺序恰好把真解释器放在前面，所以刚才敲 `python` 跑起来的是 3.12.9。换一台机器、或者哪天 PATH 顺序变了，同一条命令就会落到另一个程序上。

这解释了一个经典现象：`pip` 说「安装成功」，`import` 却说找不到。不是安装失败，而是**装进了解释器 A，运行时用的是解释器 B**（依赖管理到 C00-02 再展开，这里只要记住这条因果）。

还有一条容易漏掉的通道：**编辑器里「选中的解释器」跟终端里敲 `python` 是两条独立的通道**。编辑器用它来跑代码、做补全；终端用它来执行命令。两边选了不同的 Python，就会出现「终端能跑、编辑器不能」或者反过来。

验证命令只有一条，先记住它：

```powershell
python -c "import sys; print(sys.executable)"
```

它打印的是**此刻真正在执行的那个解释器**的路径。对比一下：`python --version` 只能证明「有个 python 能跑」，证明不了「是哪一个」——两个不同安装完全可能都是 3.12。

## 3. 三个路径，不要混

编程里最容易混的三个「路径」其实回答三个不同的问题：

| 问的问题 | 表达式 | 会不会随 `cd` 变 |
|---|---|---|
| 这个脚本文件在哪？ | `__file__` | 不会 |
| 我现在站在哪个目录？ | `os.getcwd()` | 会 |
| 是谁在跑我？ | `sys.executable` | 不会（换解释器才变） |

本机实测，同一个脚本在三个目录启动（Python 3.12.9）：

| 启动方式 | `__file__` | `cwd` | `sys.executable` |
|---|---|---|---|
| 在脚本所在目录：`python show_paths.py` | 脚本的绝对路径 | 脚本所在目录 | 同一个 `python.exe` |
| 在父目录：`python c00-01-probe/show_paths.py` | 同上，没变 | 父目录 | 同上 |
| 在工作区根：`python "_scratch/c00-01-probe/show_paths.py"` | 同上，没变 | 工作区根 | 同上 |

一句话结论：

> `__file__` 跟着脚本走，`cwd` 跟着终端走，`sys.executable` 跟着「谁在执行」走。

第二句话更关键，也是本单元唯一需要背下来的一句：

> Python 里 `open("data/x.csv")` 这类相对路径，基准是 **cwd**，不是脚本文件所在的目录。

## 4. 最小例子：同一个脚本，换一个目录，两种结果

目录结构（放在 `subjects/13-AI技术学习/练习/c00-01/` 下）：

```
c00-01/
├─ show_paths.py
└─ data/
   └─ sample.csv
```

脚本最后一行读 `data/sample.csv`。实测结果：

| 你在哪跑 | `cwd` | `open("data/sample.csv")` |
|---|---|---|
| 站在 `c00-01/` 里跑 | `...\c00-01` | 成功 |
| 站在上一级跑 `python c00-01/show_paths.py` | `...\练习` | `FileNotFoundError` |
| 站在工作区根跑，用绝对路径指向脚本 | 工作区根 | `FileNotFoundError` |

代码没改，脚本也没坏，变的只是「你站在哪」。所以：

> 看到 `FileNotFoundError`，第一反应不是改代码，而是问两件事：**我现在在哪（`Get-Location`）**、**这个相对路径从哪算起**。

三条应对，按优先级：

1. **先 `cd` 到脚本所在目录再跑**——最省事，也最不容易错，本项目默认这么做；
2. 让路径跟着脚本走，而不是跟着终端走——写成「脚本目录 ＋ 相对路径」（涉及的 `os.path` 细节到 C00-05 再讲，现在只要知道存在这条路线）；
3. 顶用绝对路径——只用于临时排查，写死路径不进项目。

## 5. 终端最小命令表（PowerShell，本机 5.1）

| 目的 | 命令 | 说明 |
|---|---|---|
| 我现在在哪 | `Get-Location` 或 `pwd` | 输出的就是 cwd |
| 这个目录里有什么 | `Get-ChildItem` 或 `ls` | 看文件名对不对 |
| 换目录 | `Set-Location ..` 或 `cd ..` | `..` 是上一级 |
| 这条命令会执行哪个程序 | `Get-Command python` 或 `where.exe python` | 后者会列出全部命中项 |
| 运行脚本 | `python 脚本名.py` | 相对路径也以 cwd 为准 |
| 打断正在跑的程序 | `Ctrl+C` | 死循环、卡住时用 |

两个本机特有的坑，先记下来省一次折腾：

- **`where python` 在 PowerShell 里查的不是路径**，`where` 是 `Where-Object` 的别名，用于筛选管道里的对象。要列文件位置必须写 `where.exe python`。
- **本机没有 `py` 启动器**（`where.exe py` 无结果）。很多教程写 `py -3 xxx.py`，在本机一律换成 `python xxx.py`。

## 6. 动手骨架（结构给全，核心你自己补）

在 `subjects/13-AI技术学习/练习/c00-01/` 下新建 `show_paths.py`：

```python
import os
import sys

print("script file:", __file__)
print("cwd        :", os.getcwd())
print("executable :", sys.executable)

# 你补：读取同目录下 data/sample.csv，打印第一行
# 提示：用 open(...) 配 with，遇到 FileNotFoundError 就先把 cwd 打出来看
```

数据文件 `data/sample.csv` 自己造两行，例如 `subject,minutes` 和 `数学,45`。

然后**先预测、再运行**，跑三组：

1. 站在 `c00-01/` 里：`python show_paths.py`
2. 站在上一级：`python c00-01/show_paths.py`
3. 站在工作区根，用绝对路径指向脚本

每组都先写下你认为三行输出分别会是什么，再去运行对照。**预测错的那一组，才是这一节真正有用的部分。**

小提醒：终端里标签先用英文（`script file:` 这种），中文标号在本机控制台容易出编码乱码，干扰你判断「是路径错了还是显示错了」。编码问题到 C00-05 再处理。

## 7. 常见报错的第一次反应

| 屏幕上出现 | 大概率原因 | 第一次该做什么 |
|---|---|---|
| 无法将 `python` 项识别为 cmdlet、函数、脚本文件或可运行程序的名称 | PATH 里没有它，或拼错了 | `Get-Command python`；确认装在哪 |
| `ModuleNotFoundError: No module named 'xxx'` | 包装在另一个解释器里 | 先打 `sys.executable`，跟 `pip` 装的那个环境对照 |
| `FileNotFoundError` | cwd 不对，相对路径算错了基准 | 先打 `os.getcwd()`，再看相对路径 |
| 中文乱码或 `UnicodeEncodeError` | 控制台编码与文本编码不一致 | 先用英文标签验证逻辑，编码留到 C00-05 |

## 8. 本单元验收（自己能答上来才算）

1. 指着一条实际输出，说出「这就是这次真正在跑的解释器」，并说明你凭什么这么判断。
2. 换一个启动目录，说清楚哪一行变了、哪一行没变、为什么。
3. 解释一次「为什么这个相对路径在这里找不到」，并当场改对。

课程设计里的三条验收依据是：能指出实际解释器；换运行目录后能解释相对路径变化；自述会路径时允许用现成输出直接验证。这里是同一件事的复述版。
