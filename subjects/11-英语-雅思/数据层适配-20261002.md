> 来源：2026-10-02 **只读**代码审计（未改任何文件，只用 `python -B` 做纯读探针）。
> 目的：让雅思的**连续分档**（0–9，0.5 一档）与**过程指标**进入证据链，同时**不动**现有 10 门课的判定。

## 一、审计结论（六条，均有 文件:行号 证据）

1. **校验是分层的**：`target_results[tid]` 内未知键 = **ERROR 硬拒收**（`tools/validate_attempts.py:138-140` + 白名单 `tools/learninglib.py:263-266`；写入路径 `append_attempt.py:144-165` 会**回滚该行**）；
   而**事件顶层完全不做未知键检查**（`validate_attempts.py:87-89` 只查 REQUIRED 是否缺失）→ 顶层乱加键会被静默接受、永久留在日志里，**且不能用 `record_correction.py` 订正**。
2. **判定不受未知键影响**：`learninglib` 全程"按名取值 + 缺省回退"，未知键被忽略，不报错、不参与判定（合成事件实测 `independence_blockers()` 返回 `[]`，行为不变）。
3. **指纹是原始字节 sha256**（`derive_state.py:375-395`，只覆盖 `attempts.jsonl` + `corrections.jsonl`）。
   收尾顺序是「先重建(step 3)、后核对(step 10)」→ **追加带新字段的事件后照常跑 `session-close` 不会 FAIL**；
   唯一失败模式是「**追加了事件却没重建**」。
4. **指纹不覆盖** `goals.yaml` / 题目 frontmatter / `hurdles.jsonl` / `policy.yml` → 改这些**不会 FAIL，但会静默陈旧**（必须手动重跑收尾；本次新增 `ielts-english-75` 即如此处理）。
5. **现有连续数值字段都不能借用**：`active_minutes` 语义是时长；`predicted_confidence` 校验了但**无人读**；
   SM-2 的 `q`(0–5) 只在 `state/reviews.jsonl`（**0 字节**、活动工具链不读）→ 语义与载体都不匹配。
6. **雅思的 4+4 维度已经是独立目标**（`en.write.tr/cc/lr/gra`、`en.speak.fc/lr/gra/pr`）→
   分档**天然挂在目标级**（`target_results[tid].band`），不需要新容器、也不需要给「写作」造一个假的父目标。

## 二、落地方案（审计推荐：**分两阶段**）

### 阶段 1 —— 现在做（1 行 + 文档，零判定风险）

| 改动 | 位置 | 作用 |
|---|---|---|
| `PER_TARGET_KEYS` 追加 `"band"`、`"metrics"` | `tools/learninglib.py:263-266` | **一行同时解锁三处**：校验接受、目标级订正允许（`learninglib.py:539,597` + `record_correction.py:84-85`） |
| 文档化两字段语义 | `learning/README.md:76-90` | 写明「**过程指标**，不参与独立通过／等级判定」 |

- **人读兜底**：分档与计量同时写进 `learning/attempts/<task>-attemptN.md` 过程详档（本仓既有的「过程详档」约定，`artifact_ref` 指向）。
- **风险：低**（纯放宽白名单；旧事件本来就没有这两个键）。
- **效果**：Phase 0 基线题可以**立刻开跑**，分档从第一天起就以正确形状落盘，**不需要日后迁移**。

### 阶段 2 —— Phase 0 数据出来后再做（自动化曲线）

| 改动 | 位置 | 风险 |
|---|---|---|
| `band` 0–9 半档、`metrics` 为对象的**类型校验** | `tools/validate_attempts.py`（`:149` 之后加分支） | 低 |
| 目标字典新增 `bands` / `band_first` / `band_latest` / `band_best` | `tools/derive_state.py`（收集 `:239-253`、输出 `:281-329`） | **中**（动派生主流程，但只**新增键**） |
| 新增 ②b「分档曲线」小节 | `tools/current_state.py`（② 段之后） | 低（**仅当存在分档数据时输出** → 现有 10 门课输出逐字不变） |

> **为什么分两阶段**：Phase 0 只需要「事件能合法地写下分档」，不需要「视图能渲染曲线」。
> 先用 1 行解锁 + 过程详档兜住人读，等拿到真实数据结构再改派生链——**避免在抽象状态下设计字段**。

## 三、禁止清单（做了会**立刻打断**现有 10 门课）

1. **不要**把 `band` 写进 `initial_result` / `final_result` → 枚举白名单直接 ERROR。
2. **不要**把 `band` 加进 `REQUIRED` → 现有 36 条事件立即全部「missing field」，连锁 FAIL。
3. **不要**让 `band` 参与 `independence_blockers()` 或 `level` 判定 → 会改 10 门课的等级与覆盖状态。
   （`goals.yaml` 的 `ielts-english-75` acceptance 已写死：「分档是过程指标，不替代无帮助通过的等级判定」。）
4. **不要**改 `source_fingerprint()` 算法（`derive_state.py:375-395`）→ 历史 `learner-state.json` 会全部不一致，第 ⑩ 步必 FAIL。
5. **不要**新增 STATUS 字段（`sync_status.py:138-147`）→ 无法被第 ⑩ 步核对，会变成新的「两处各写一份」。
