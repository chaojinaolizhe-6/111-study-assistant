# 周计划（plan/）

跨课程学期排期：tutor 模板本身没有"结合课表及截止日期的时间排期"（全库检索 deadline/calendar 零匹配），
这是确认缺失后补的唯一脚本。规划单位是**能力目标与证据**，不是"周几学完第几章"。

## 两个排期文件，分工明确（2026-09-30 维护加）

| 文件 | 生成者 | 管什么 | 何时看 |
|---|---|---|---|
| `plan/schedule.md` | `tools/schedule_reviews.py` | **复习与再测的日期化排期**（记忆维护 / 能力再测 / 题目截止 / 外部截止 / 目标节点），每条带**最早开始、截止、设备、预计时长** | 每次收尾后；每天开工前看第①节 |
| `plan/week-plan.md` | `tools/plan-week.py` | 跨课程**周计划**（三队列争时间预算、设备时段、容量约束） | 改了 `plan/inputs.yml` 后 |
| `plan/today-<中国日期>.md` | **人工**（导师与学习者确认后写） | 当天时间窗与清单；**当天以它为准** | 每次会话开头 |
| `plan/handoff-CURRENT.md` | `tools/handoff.py` | 跨窗口续学入口；动态部分**引用 `state/current.md`** | 换会话时 |
| `state/current.md` | `tools/current_state.py` | **当前状态的唯一事实源** | 任何时候想知道"到哪了" |

⚠ **日期基准**：一律用**中国日期**（`tools/timebase.py`，UTC+8）。系统/文件时间戳是英国时间，
英国 17:00 之后中国已是次日——直接用系统日期会把"明天"排成"今天"，也会把结转算错一天。

⚠ **未来才开放的任务不提前安排**：`schedule.md` 里每条都有 `not_before`（如"已有独立通过 + 2 天延迟"），
早于该日期只出现在第③节"未来才开放"，**不进今天清单**。

⚠ **设备可用 ≠ 全时段能专注**：`device` 只表示"要用什么设备"；`capacity.weekly_minutes` 为 `null` 时
**不做容量校验、也不编造总量**。

## 用法

```
python -B tools/plan-week.py --inputs plan/inputs.yml --root . --out plan/week-plan.md
```

- `inputs.yml`：课程、作业（截止日期+预估耗时+所需设备）、设备时段、余量系数、周容量、阶段比例。
- 三条队列竞争同一时间预算：
  - 记忆维护：tutor 到期概念复习（扫描 subjects 概念笔记 frontmatter 的 due，与 state/due.md 同源）
  - 能力建设：learning/tasks/ 中未完成的题目（worked-example 归"概念"类，其余归"能力"类）
  - 修复与再测：learning/attempts.jsonl 中 diagnosis_status=pending_probe/confirmed 且未答对的作答
- 输出 `week-plan.md`：每天分"平板（白天）/电脑（晚上）"，截止日期优先，任务带类别标签，排期报告与告警。

## 规则

- 设备约束：pc 任务只排电脑时段；tablet 任务只排平板时段；any 任务优先白天平板。
- 截止约束：任务只排在截止日期之前；排不下 → 显式告警（提示提前或拆分，不靠平摊制造可行性）。
- 大任务可跨天拆分。
- 阶段时间比例（可选）：每类别每日配额 = 当日总容量 × 比例，防止到期复习挤占独立解题。
- 周容量约束（可选）：Σ承诺任务 ≤ (1-buffer) × weekly_minutes；超出 → "容量不足"告警，要求缩减范围。
- 未知项保持未知：assignments 留空、weekly_minutes 填 null，不编日期。

## 已知限制（2026-09-26 第三方评估后补充）

- **时区与"学习日"边界（2026-09-27 补）**：系统/文件时间戳是**英国时间**，学习者本地是**中国大陆（UTC+8）**，当前差 **+7 小时**（夏令时）。
  → `inputs.yml` 的 `today`、`plan/today-YYYY-MM-DD.md` 的文件名与时间窗**一律按中国时间**；接近午夜时先换算再落笔（换算命令与规则见 `.tutor/config/time-environment.yml`）。
- **不支持当日临时时间窗**：脚本只认 `inputs.yml` 里的固定时段（如"白天平板 09:00–18:00"），无法表达"今天只学到 13:00"这类临时窗口。
  → 临时窗口写在 `plan/today-YYYY-MM-DD.md`，**当天以该文件为准**；临时窗口**不跨天沿用**。
- **不编造截止日期**：题目未写 `due` 时，脚本用"默认视界（today+days）"占位，输出中标记为
  「**无真实截止日期**；排期占位 …」，**不得当作真实作业截止日期**。真实截止写入 `inputs.yml` 的 `assignments`。
- 改了 `inputs.yml` 后**必须重新生成** `week-plan.md` 再引用，否则聊天安排会与文件不一致。

## 脚本强制 vs 助手执行（2026-09-26 第三方评估后补充）

分清哪些是**程序保证**的，哪些只是**助手手动遵守**的——不要把后者说成前者。

| 规则 | 谁保证 | 说明 |
|------|--------|------|
| 设备约束（pc 只排电脑时段 / tablet 只排平板时段） | **脚本** | `build_slots` + `compatible()` |
| 截止日期优先、当天仍可排 | **脚本** | 排序键 `(due, -est_minutes, course, id)` |
| 每时段容量与余量系数（70%） | **脚本** | `capacity = min(max_minutes, 窗口长) × slack` |
| 未配置周容量则不校验容量 | **脚本** | 本工作区 `weekly_minutes: null`，**没有**总量上限保证 |
| 程序默认日期标为"排期占位" | **脚本** | `due_is_placeholder` |
| **复习/再测的最早开始日期**（`not_before`） | **脚本** | `schedule_reviews.py`：`not_before = 上次独立通过 + min_delay_days`，**必然 ≥ 通过日期**，不会排进过去 |
| **每日主任务上限**（默认 2 条） | **脚本** | `schedule_reviews.py` 的 `MAIN_TASKS_PER_DAY`；其余进候选队列 |
| **昨日未完成项的处置**（结转/延期/取消） | **脚本提示 + 助手执行** | `--carry-over plan/today-<昨天>.md` 扫出未勾选行并**要求逐条显式处置**，脚本不自动删 |
| **已作答的题不再当待办** | **脚本** | `reviews.load_task_due_dates` 过滤掉已作答/已提交的题（否则已完成事项会一直在"已逾期"刷屏） |
| 「真实截止 > 当天选科 > 无截止任务」中的**"当天选科"** | **助手手动** | 脚本**没有**该字段；选科优先靠助手在当天文件里体现 |
| 「未完成任务结转到哪天」 | **助手手动** | 脚本只**列出**待处置项，具体处置由助手与学习者决定 |
| 「临时时间窗」（今天到 13:00） | **助手手动** | 脚本只认固定时段；写在 `plan/today-YYYY-MM-DD.md` |
| 「有余力不加难度」 | **助手手动** | 无程序约束 |

> 结论：脚本保证的是**设备、日期、容量**三件事；**科目优先级、结转、临时窗口靠助手执行并在当天文件留痕**。改完 `inputs.yml` 必须重跑脚本。

## 检查点约定（卡题时）

独立推导块 35~45 分钟后判断：
- 仍在产生新推理 → 用缓冲延长；
- 原地打转 → 转诊断或请求提示；
- 明确缺前置 → 生成短修复任务；
- 疲劳低级错误 → 保存状态（已完成什么/失败原因/当前障碍/下次先做什么），换低负荷任务或结束。
